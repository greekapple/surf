# "Camera" panel on the spot page (bayarea-cams-wire, 2026-11-10)

**Display.** Under the amended camera rule (PRODUCT.md): display is OK for public domain, explicit embed terms, or an owner-enabled YouTube stream; credit it, load on tap, state live status honestly; AI analysis still needs written permission or public domain. The usable-now cameras of `docs/forecast/BAYAREA-CAMERAS.md` (rows in `camera-sources.json`), shown on the spot (forecast) page between the daylight row and the conditions. Nothing is analysed, copied or stored; Home and the map have no panel. Data: `src/data/liveCamsSourced.ts`, generated by `scripts/build-live-cams.mjs` from the camera rows (a test checks the committed file equals the generator's output; a row must say display permission, live on its check date and not be an excluded host).

**The still.** Loaded by the visitor's browser from USGS's own host. Its time is the owner's `Last-Modified` header, which the browser cannot read (the bucket sends no CORS headers), so the Worker's `/api/cam-meta?id=usgs-dream-inn-c2` (`services/cam-meta.mjs`) makes one HEAD request to the fixed URL and returns only the time (kept 5 minutes; 60 s after a miss; an unknown id is a 404; no image is fetched or stored). The panel says "Frame posted 9:43 AM PST (7 min ago); the time stamped on the picture is when USGS took it, usually 10–30 min earlier · new frame every 30 min in daylight. (Observed 2026-11-10: a frame stamped 9:00 PST was posted 9:13; a frame stamped 9:30 PST was posted 10:01. The row says about 10 minutes.)" in the spot's zone (so "posted", not "taken"); the age is re-read every minute, the time is asked again every 30 minutes and whenever the tab becomes visible, and the picture's address carries the returned time so the caption and the picture always match; it and never shows a frame it cannot date: older than 2 h = "Offline. The newest frame was posted … 3 h ago, so it is not shown. USGS collects images in daylight only; an old frame means the camera system may be offline"; no readable time = "Offline or unreachable … a frame whose age is unknown is not presented as live". At night, when the last frame was posted near or after sunset: "No frame since dusk; USGS collects in daylight only". Credit: the row's own attribution, "U.S. Geological Survey, Pacific Coastal and Marine Science Center (public domain)", with a link to the USGS page.

**The streams.** A lite embed: our own poster (never YouTube's thumbnail: the Chamberlin thumbnails are a 2020 storm photo), titled "Video stream · <owner>" with "Live when we last checked it by hand (Nov 10, 2026). Tap to load YouTube's player; it shows whether the stream is live now." Nothing is requested from YouTube, ytimg or googlevideo until the visitor taps; then the IFrame API loads and the player autoplays. The hand check was a page read plus a headless embed on 2026-11-10 (Linda Mar re-checked the same day through YouTube's oEmbed: HTTP 200, author "Linda Mar Beach Cam", embedding on, operator still unnamed; recorded in the row's `recheck`); **SWELLO does not monitor the streams**, and does not probe YouTube itself (its terms forbid automated access). So **"Offline" for a stream comes from the player after the tap**: an error code (100 removed or private; 101 and 150 embedding turned off by the owner; 153 "the YouTube player could not verify this site (a SWELLO setup problem, not the camera)"), the player's own `isLive` = false (the player is paused and dimmed: "a recording or an ended broadcast"), the end of the stream, or no player within 12 s ("could not load"). Credits: "Chamberlin Nature (pacificaview.net), live cam via YouTube" with links to the stream and the channel; "Linda Mar Beach Cam, live cam via YouTube" (the row publishes "Live cam: Linda Mar Beach Cam via YouTube") with its links.
