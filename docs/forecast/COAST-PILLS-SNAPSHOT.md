# Coast pills: the daily forecast for coasts the map has not loaded (pills-snapshot, 2026-11-10)

**Problem.** Zoomed out, a far coast read "Hawaii · Not loaded yet · 152 spots" because the map only loads nearby spots.

**Endpoint** `/api/coast-ratings?t=<ISO whole hour>` (`services/coast-ratings.mjs`, `src/services/coastSnapshot.ts`). It reads R2 only (the status file, then `howright/v2/shown/<UTC date>.json` of today, yesterday or the day before; a capture counts as complete when the status file says so for that day or every catalogue spot is in it) and makes no Open-Meteo call and no write. For the hour it **re-rates every captured spot with the current engine**: the stored marine and wind hours of that hour go through `normalizeOpenMeteo`, `toLegacy` and `rateForecast` (the onshore cap included), exactly as a pin's record does; the score stored in the capture is never read (the 2026-11-10 capture predates the cap: Crescent City, Brookings, Salmon Creek, Dillon Beach, Unreals and Anahola Bay differ, e.g. 55 stored against 39 "weak" now).
Each spot is judged **as of its model run**: at the older of its marine and wind retrieval times (a cached copy can be hours older than the capture), so the rating's lead-dependent ceiling counts the hours from the run to the hour shown. One (capture, hour) answer is therefore the same for everyone and can be cached.
Answer: `{ok, date, capturedAt, t, from, to, retrievedFrom, retrievedTo, spots: {id: [score|null, category|null, dark 0|1, retrievedMin]}}` (`retrievedMin` = the spot's run retrieval, minutes since the epoch); the page derives the band and the word from the category with the same functions a pin uses. `{ok:false, reason}` for an hour outside the capture's 48 hours (`outside-capture`, with the first and last hour), no complete capture (`no-capture`), a half hour (400 `bad-hour`); a failed R2 read is a 503 and never read as "nothing there". About 22 KB for 492 spots; 100 ms cold, 0 ms warm.
Caching: the capture is held 10 minutes in memory (then the status is read again so a new capture is picked up), concurrent requests share one load, "no complete capture" is remembered for 60 seconds, each (capture, hour) answer is kept as a string, the answer carries `Cache-Control: public, max-age=300`, and an ok answer is also put in the Workers edge cache (`caches.default`) where the zone has one (a no-op on workers.dev; a "not available" answer is never put there).

**Page.** Per selected hour one request, asked once the hour has held for 150 ms (scrubbing the time strip asks for the hour it stops on) and kept 10 minutes; an HTTP or network failure is tried once more after 3 seconds; a well-formed "not available" answer is final. While the request is in flight a pill with nothing else to show reads "Loading forecast…", never "Not loaded yet". A spot with a live record at the hour keeps its live value. A spot whose live load finished with no record at the hour (a failed load) keeps its pin's "not rated", so a pill cannot contradict its pin. Only a spot that is not loaded (or still loading) takes the daily-forecast value, counted apart from live:
- the pill's visible key carries the age of the best spot's model run: "Best, forecast 9 h old: Solid · <spot>" ("After dark, forecast 9 h old ·" in the dark); on a phone, where the pill is narrow, the key stays "Best: Solid" and a line under it reads "striped = forecast 9 h old". "Best of covered/total" whenever spots stay uncovered; "Best:" when the best is live;
- the aria label and the tooltip carry ONE source line: "Daily forecast: the model run retrieved <time> [to <time>] (<age> old), rated with the current rules as of that run; not live. A pin loads the newest run, so the two can differ.", and the band counts split into live and daily forecast; the bar key explains the stripes;
- the bar draws the daily-forecast segments in the band colour with diagonal stripes (`.xc-snap`); the unloaded ones stay dashed;
- a live value wins a tie of score; a dark spot is never the best while a daylit one is rated; nothing is averaged;
- an hour outside the capture's 48 hours, no capture or a failed request: "Not loaded yet", as before. Pins are unchanged.

**What the daily forecast is.** Same engine and same inputs as a pin, but from the capture's model run (retrieved <time>, up to ~2 days before the hour shown, plus the age of any cached copy); a pin loads the newest run, so the two can differ. (It is not a different method: the capture holds the same Open-Meteo marine and wind hours a pin reads and the rating is the same `rateForecast`.)
