# T-002 QA: browser journey suite

Script: `~/Development/ai-system-setup/playwright-toolkit/swello/journeys.mjs` (Node ESM, Playwright, Chrome channel, 1440x900).
Run: `zsh -lic 'cd ~/Development/ai-system-setup/playwright-toolkit && node swello/journeys.mjs [baseUrl]'`
Build under test: `ab4367c`, dev server http://127.0.0.1:5180, live data mode. No app code changed.

## Journeys
Each runs in a fresh context (own localStorage). Journeys 1, 2 and 4 seed an onboarded profile with favourites Linda Mar and Ocean Beach; 5, 6, 7, 8 start from a fresh state.
1. Home: select the other favourite card -> hero heading, card `aria-pressed`/active class, spot picker and `?spot=` follow.
2. Home card "Forecast" -> `/forecast`, `?spot=` slug, spot picker, page heading and picker listbox selection match; survives reload.
3. Forecast hour: ArrowRight x6, ArrowLeft back (metrics restore exactly), PageDown, click a "Next hours" row, click the timeline, Home/End. After every step the readout time must equal the timeline slider's `aria-valuetext` hour, and readout Hs, swell period and wind must equal the first "Next hours" row for that hour; Hs also equals the slider tooltip text. Clicked row values must equal the readout. At least 3 distinct metric tuples and one-to-one time labels across hours.
4. Explore: choose the other spot in Discover list -> panel, aria-current, URL; navigate to Forecast in-app -> spot, URL, heading and shared hour kept.
5. Quiver: add board (form), edit name/volume, check list/showroom/localStorage, reload, check list and showroom again.
6. Personal: set name and Heights = m, reload, Home greeting "Hello, Journey." and bulletin/cards in metres; stored profile; switch back to ft persists.
7. Wave Scale: WebGL context; height slider (readout, aria-valuetext, stage aria-label, ratio text), keyboard ArrowUp on stage, Riding/Paddling, camera Profile, Metres/Feet, Reset. Canvas pixels are compared through 32x32 luminance thumbnails of a canvas screenshot against a measured idle-noise baseline (fails if idle noise is not ~0, requires change > 4x noise); the `.tag3d` label DOM and `swello-ui-v1` storage are also asserted. Functional only, not visual quality.
8. Theme: Dark -> `data-theme`, `swello-theme`, body background, reload; Light -> reload; persists on another route.

Unexpected `pageerror` or console errors fail the journey (ignored: NDBC/ERDDAP/CORS, OSM tiles, favicon). Failure screenshot goes to `swello/artifacts/journeys/<stamp>/`.

## Results (real runs)
Test-script defects fixed while developing (not app defects): stale card locator after re-render (J1/J2), timeline click coordinates taken before scrolling (J3), time-label uniqueness check colliding with "now" hour (J3).

Final script, three consecutive runs: each printed `8/8 journeys passed; no unexpected browser errors`, exit 0. Per-journey time: J1 3.0 s, J2 4-6 s, J3 5.4 s, J4 2.1 s, J5 3.4 s, J6 4.1 s, J7 13.3 s, J8 4.6 s; about 40 s total plus Chrome start.
(Earlier, with the J3 uniqueness bug, two runs gave 7/8 with exit 1, and the failure screenshot was written, which confirms the exit code and artifact paths.)

## App defects
None found in this build.

## Known limits
- Live data dependent: needs Open-Meteo reachable; hours and metrics are compared against the app itself (readout vs list vs slider), not against provider data.
- Desktop 1440 only; mobile layouts and tab bar not covered here (see swello-qa.mjs).
- J7 pixel check is a coarse thumbnail diff; it proves the scene redraws, not that geometry or proportions are right.
- Journeys stop at their first failing check; the favourite-card journeys assume exactly two seeded favourites exist in the live spot set.
- Check strength was not mutation-tested against injected app faults.
